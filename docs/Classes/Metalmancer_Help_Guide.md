# Metalmancer Help Guide

## Class ID

- `metalmancer`

## Availability

- Selectable class ID exists.
- Currently documented as visible in the class selector but temporarily disabled.

## Overview

Metalmancer is the only class with a currently documented class-specific inventory/resource loop and action set. Its implemented systems include extra inventory behavior, ore storage, stationary ore gain, and golem-related actions. Some Metalmancer action and tier handling details are documented as incomplete.

## Abilities

- Open/use Metalmancer extra inventory while the player has the Metalmancer class.
- Use Metalmancer-only items and summoning staffs.
- Summon a Metalmancer Golem when requirements are met.
- Reforge the active Metalmancer Golem through staff interaction where the staff/action path supports it.
- Gain ore through Stationary Resonance while standing still on solid ground.
- Gain increased Stationary Resonance output when a golem is co-resonating nearby.

## Benefits

- Access to Metalmancer-attuned equipment, when such equipment is authored.
- Access to Metalmancer class-locked chests.
- Access to Metalmancer extra inventory/storage behavior.
- Access to the Satchel of Samples as an intrinsically Metalmancer-bound utility item.
- Access to ore-based golem utility systems.

## Incentives

- Choose this class to use the documented extra inventory and ore resource loop.
- Choose this class to use Metalmancer-only staffs/items.
- Choose this class to access golem utility behavior.

## Team roles

- Utility companion support through a summoned golem.
- Resource-management role through ore/satchel mechanics.
- Additional team role details: TBD.

## Class restrictions and access

- Can use/wear equipment attuned to `metalmancer`.
- Can open Metalmancer class-locked chests.
- Can use Metalmancer-only items.
- Can use the Satchel of Samples.
- Non-Metalmancer players should not retain Metalmancer extra inventory mirror data after class changes.
- Active golem count is limited to one nearby golem per Metalmancer by the documented implementation assumptions.
