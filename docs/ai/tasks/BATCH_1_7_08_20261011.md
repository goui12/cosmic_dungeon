## Implemented card8
- Newly crafted server recipe outputs receive native MAX_STACK_SIZE64 on a copy. Full effect, container, name, lore, ownership and other components remain intact. Only the new recipe output is transformed; existing ordinary/authored/chest potion stacks are never scanned or rewritten. No global stack limit or item registry changes.
- Cursor placement helper returns an independent one-item result only for an empty cursor or an identical full-component stack below its limit. Full/incompatible cursors produce no result and mutate neither input. Potion variants, names, custom data and old ordinary capacity remain distinct.
- Shift placement helper plans exactly one output, preferring hotbar merges then empty hotbar slots, then main-storage merges/empty slots. Armor/offhand are not overflow storage. All placement occurs on a deep copy; failure after a partial candidate merge leaves the source unchanged. Existing trusted multi-item recipes retain bounded all-or-nothing placement through the same internal planner.
- Batch7 inventory crafting now produces these stacks using the unchanged Batch6/7 transaction/fuel protocol. Repeated identical crafts merge, one remaining space accepts one, and the next click with a full stack/inventory debits nothing. Native player saves retain count and stack component; fuel/metrics/consent protections remain in force.
- Native menu split/merge/drag/hotbar/offhand/Shift paths honor per-stack capacity and full component identity. Native drinking consumes one and returns one bottle, replacing the last potion or adding/dropping the remainder when necessary. Main/offhand throws create one one-item projectile and consume one. No broad consumption mixin is necessary.
- Existing all-potion trade exemption and ownership projection preserve the stack; cancel/disconnect returns it once. Actual death provenance, partial pickup and accepted resurrection retain count/components without copying physical drops into a second inventory.
