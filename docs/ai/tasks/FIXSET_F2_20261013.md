## Changes and authority
Reusable native Ready widget provides a restrained two-second green pulse only for enabled Ready actions; hover/focus holds a stable brighter native highlight. Disabled, pending and Not Ready states retain native presentation. Server snapshots remain authoritative. A bounded HUD pending wait handles rejected/throttled/no-change actions without new traffic or speculative readiness.

Lobby resource choices are mutable only during ASSEMBLY/READY_CHECK. Accepting Start Adventure advances to QUEUED on the same server thread and rejects both stale and forged-current-revision changes. Preparation preserves the freeze. Canceling entry returns to pre-game. Active-run changes reject through the existing handler for normal/Extra inventory and Tamsin contexts. Successful entry transfers only from frozen PREPARING into an exact matching active roster; replay never replaces nonempty saved values.

No schema/network migration: existing resource_sharing_v1 keys and unknown fields remain intact. Legacy missing/unknown choice is fail-closed. Completion/forfeit/retirement uses existing lifecycle cleanup; a new pre-game group requires an explicit choice. Online/alive/roster/dimension/completion-exit/sealed-run and transaction guards still run immediately before each debit. Frozen consent never keeps an ineligible donor usable.
