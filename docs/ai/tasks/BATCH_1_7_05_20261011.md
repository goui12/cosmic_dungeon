## Implemented
- Server-world-local Dungeon Instance Metrics/<instance-UUID>.xml records each run, with version1, stable server/world UUID, deterministic instance UUID from server UUID/run number, lobby party UUID (deterministic fallback for legacy), player UUID/name/class snapshots, dungeon/difficulty, UTC epoch-millisecond start/update/end, coverage and outcome.
- Original participant roster survives removal. ACTIVE checkpoints become immutable COMPLETED, ABANDONED (including manual reset), or STARTUP_ABORTED records before cleanup/reset removes counters. Restart, logout and Village visits alone do not finish runs.
- Reuses accepted D1 kill attribution and its duplicate-death guard, including companion and delayed environmental credit. Counts hostile mob registry IDs and overall kills, deaths, actual damage and healing received, and spawners successfully removed by harvesting or authorized fireworks. Canceled deaths/breaks, protected blocks and wrong tools do not count. Existing reward/scoreboard rules remain separate.
- Server totals.xml and players/<player-UUID>.xml retain finalized-run counts, completed/aborted counts, aggregate statistics and latest10 completed/aborted runs sorted by end time. Different instances and players remain separate.
- Typed resource quantities used/contributed and transaction/donor/recipient/skill/item/time fields are versioned now. ResourceEvent enforces participant custody. Actual shared crafting debits, allocation, notifications and resource-event production remain Batch6; no invented resource consumption.
- Existing runs upgraded mid-run use PARTIAL_LEGACY; historical unclassified kills remain explicit cosmicdungeon:unclassified rather than guessed mob species. Runs predating this recorder cannot be reconstructed if their source counters were already deleted. Full combat coverage is D1; other dungeon lifecycle snapshots are labeled partial.

## Persistence, recovery and bounded cost
Existing cosmicdungeon_d1_objectives_v1 maps gain additive metrics_v1: keys, no schema rewrite or migration. Old worlds without metrics start safely. Original names/classes/roster stay in the run store; source counters remain until terminal archive success. ACTIVE archive floors restore stale SavedData counters before startup recovery; a hard crash can still lose events after the latest world save/checkpoint. Exactly-once guarantee covers finalization/totals, not unsaved gameplay events.

Atomic same-directory replacements and forced file contents retain previous snapshots on failure. pending.xml stores exact afterimages for each member total, server total and terminal run. Recovery validates all schemas/identities/destinations first, rewrites those same images, commits the final run last and removes the journal last. Crashes between writes replay without increments or duplicate totals. Existing terminal files cannot be changed by conflicting replay or ACTIVE checkpoints. I/O/schema failure logs at most once/minute and holds destructive cleanup/reset for retry. Unsupported atomic rename fails closed. Filesystem/hardware power-loss durability still depends on storage honoring flush/rename; no portable directory-fsync guarantee is claimed.

Identity is persisted separately. Missing identity in a nonempty archive, unknown future versions/fields, malformed XML, external entities, oversized files, foreign IDs and corrupt journals are retained and rejected. Do not delete pending.xml to bypass recovery. Rollback to an older mod leaves archive files intact but stops recording; preserve a stopped-server copy before changing versions. Additive current-run keys remain readable by older builds. Returning after unrecorded gameplay is not retroactive complete coverage.

Hot callbacks update memory/SavedData only. One active instance is checkpointed every100 server ticks (5seconds at20TPS); six active slots receive one pass per30seconds, subject to existing hasTime scheduling. Shutdown and successful lobby entry also checkpoint. No new threads, heap setting, runtime dependency, network payload or per-tick inventory scan. Six members/run,512 keys/statistic map,1024 reserved resource events,512KiB individual XML and8MiB journal limits bound serialization. Model maps and transient DOM allocations are proportional to these caps; no entire-history in-memory index. Archives intentionally grow on disk; totals/last10 are bounded per player, total player file count grows with server population. Exact representative6-player/128-mob size and timing are in test output/completion evidence. Future event retention must preserve these bounds or introduce explicit segmented storage in Batch6.

## Operator lookup and rebuilding
Use Java21 while the server is stopped, or on a separate complete copy of the archive. The store is single-writer; do not run its CLI against a live server archive.
```text
java -cp cosmicdungeon-1.7.5-alpha.1.jar net.goui.cosmicdungeon.dungeon.metrics.RunMetricsStore history "<world>/Dungeon Instance Metrics" <player-UUID>
java -cp cosmicdungeon-1.7.5-alpha.1.jar net.goui.cosmicdungeon.dungeon.metrics.RunMetricsStore rebuild "<archive-copy>" "<separate-empty-directory>"
```
History prints the player's totals/last10 XML; mob id minecraft:zombie gives lifetime recorded zombie kills, stats kills gives overall credited hostile kills. Names are snapshots; UUID is the lookup key. Rebuild streams canonical finalized instance files into a separate empty output; ACTIVE runs are deliberately not totalized. Review recovered output before any stopped-server replacement. It does not query SQL, Discord or create scoreboards. Back up original files before repair; never overwrite the only archive.
