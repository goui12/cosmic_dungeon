# Batch15: Equipment and enchantments — 1.7.15-alpha.1
Approved scope: [series plan](ALPHA_1_7_BATCH_PLAN_20261010.md), card15 and approved spawner editor specification. Stop after15.

## Implemented
- Six equipment slots open a searchable, paginated item picker with slot/all filters, held-item copy, bottom selected-item preview, Save item and Cancel. Save item updates only the editor draft; main Apply commits all fields together.
- Enchantment books support left+1, right-1, Shift-left normal maximum and Shift-right removal. Normal validates item/slot compatibility, normal maximum and mutually exclusive enchantments; Advanced permits deliberate exceptions within native levels0–255 (0 removes).
- Held copying uses the actual main-hand stack snapshot taken when /spawner edit opens, retaining count, name, lore, damage and all components. Apply rejects a changed held item instead of silently copying another stack. No inventory item is granted, moved or consumed.
- Client previews resolve from trusted snapshots. C2S submits only six bounded selection/enchantment recipes; the server independently reconstructs and validates the complete result after fresh session/Developer/target/range/concurrency checks. Invalid edits change neither equipment nor other spawner fields.
- Unchanged authored equipment, including existing unsafe enchantments, survives unrelated edits. Only explicitly edited slots gain override ownership; drop chances, intrinsic/custom loot, native equipment and weighted spawn entries remain untouched. Existing captain behavior supplies its banner when head equipment is empty.
- Main rotating preview shows draft equipment without spawning/ticking world mobs. Subeditor Cancel/ESC restores the parent item draft; session shutdown/disconnect releases the editor and preview.

## Compatibility, resource cost and ownership
Network protocol31 ->32; install matching client/server builds. Existing block schema153/preset5 represent the equipment overlay, so no new persistent fields, version advance, unloaded-chunk conversion or migration scan is needed. Old presets retain their implicit six-slot ownership; metadata-only presets retain unowned slots and all unknown fields. Named preset export/loot work remains16. Back up worlds before upgrade and retain the matching prior backup/build for rollback.
One bounded six-slot draft and held snapshot per open Developer session; item/enchantment catalogs are local and paginated. No periodic inventory/world scans, runtime dependencies or resource configuration increases. Snapshot size limits remain; unusually large authored data is read-only in this editor.
Root owns common draft/rules/config, payload/service integration, native/storage tests, registration and release; one cooperative worker owns client/screen/spawner and its unit tests. No authored class-chest/loadout/rocket changes.
