## Persistence, upgrade and rollback
Same cosmicdungeon_shared_crafts_v1 SavedData ID now supports schemas1 and2. A new brewing_fuel_v1 UUID ledger contains schema1 records with charges and monotonic revision. Schema1 existing journals load unchanged. Only a successfully accepted fuel-bearing reservation advances the journal to2. Fuel plans/receipts use schema2; old schema1 transactions stay fuel-free. Unknown fields in supported records/root/plans survive; malformed/future schemas, noncanonical UUIDs, stale fuel revisions or legacy unknown-field collisions fail closed with originals retained.

PREPARED stores the exact fuel before/after transition alongside the existing inventory decision, without spending fuel. Cancellation preserves fuel and materials. COMMITTED changes fuel in the same world save as the irreversible decision; owner inventory projection/relog/receipt replay never charges again. Reload requires the ledger to match the correct PREPARED-before or COMMITTED-after image. Retiring a craft/run leaves saved fuel intact. Existing Batch6 verified owner save, recovery, resource metrics and notifications include consumed fuel powder as a real material.

No registry/item/spawner/chest migration. Do not downgrade to Batch6 after schema2 fuel data exists: it deliberately rejects the unsupported journal. Rollback requires a coordinated stopped-server backup of world journal and player/metrics saves; never delete the fuel ledger or pending custody to force compatibility. Filesystem durability limits from Batch6 still apply.
