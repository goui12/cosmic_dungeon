## Behavior and boundaries

The native projectile predicates accept vanilla firework rockets from held slots and
inventory for bows/crossbows, plus the existing dedicated rocket items. Bow creation
now constructs an aimed native FireworkRocketEntity instead of an arrow fallback.
Names, lore, firework flight/explosion components, authored class metadata and unknown
components remain intact. Existing D1 identities/effects/damage rules are unchanged;
there is no new Cinderkiss alias, power or chest/loadout rewrite. Native draw, stock
consumption, Infinity, Multishot and durability still own their normal behavior.

Rebindable Cycle ammunition defaults to R. It accepts one physical press while a bow
or crossbow is held in the world, fails closed on active native binding conflicts,
and blocks screens, typing/modals, carried items, stale menus, lost focus, death and
spectator use. Keyboard/scancode/mouse identities and platform modifier handling reuse
the skill-input foundation; a modifier key itself can be rebound. Screen releases,
disconnect and focus recovery clear held input. Current binding/unbound text appears
with exact item icon/name. Charged crossbows label selection as the next load.

Server selection invalidates on dimension/class changes even for out-and-back trips without weapon use; monotonic revisions survive invalidation.
Server selection is transient per connected player, context/class/run/hand aware and
never saved. Each native resolve/cycle scans at most37 stock positions in stable
offhand/selected-hand/slots0-35 order and groups identical full item components.
Counts do not create another type. Selection returns the actual stock reference;
it neither consumes, grants nor repairs ammunition. Missing stock selects the first
legal remaining type and announces fallback; no stock reports empty. Repeated
unchanged queries send no packet; moved same-type stock silently updates its slot;
explicit identical/empty retry notices are bounded to20ticks and cycle requests to4.
Client display/projectile prediction uses only the selected slot, never a render scan.

At actual resolve and loaded-crossbow firing, the server rechecks weapon eligibility,
actual stock, ownership, recognized D1 access and complete current class/dungeon/run
attunement. Stale weapon/hotbar requests and carried/menu states are rejected.
A charged crossbow retains its exact existing projectiles when cycling; permission
loss before firing blocks the shot without consuming the load or durability.
Network registration is35 with bounded request/view fields. Both sides need this
source revision at the later release; no saved schema/registry/migration changes,
dependencies, heap changes or background inventory/world scans are introduced.

Ordinary spawner right-click returns PASS so native bow draw/crossbow charge/fire works.
Only server-authorized Developer Shift + right-click copies equipment components.
A narrowly scoped block-use event allows that gesture through native sneak bypass,
respecting existing cancellation/use-block vetoes. A successful copy suppresses one
same-hand/exact-stack predicted item fallback within four ticks while still sneaking,
so the copying gesture does not accidentally fire a charged weapon. Later ordinary
use remains available. Skeleton bows use the existing equipment callback and native
ranged goal; no AI rewrite or spawn/preset migration is required.

The mining warning still requires20 uninterrupted actual wrong-tool breaking ticks.
Bow/crossbow holding and active item use do not warn. Release, target, dimension,
hotbar slot and tool-component changes reset it. Already warned holds stay silent.
F4 legacy/current/weighted/opaque preset preservation remains unchanged; new tests
cover exact authored bow components through block save/load and skeleton application.
Existing old-shape preset/migration regression suites remain mandatory. Rollback
requires the matching earlier client/server code; worlds need no F5 data conversion.

CI clean build and122 required native GameTests, plus fresh exact-head Codex review.

this source report does not claim gates before they pass. Datagen is not applicable.

New native tests exercise real bow use/draw/spawn for all three authored vanilla
names plus existing dedicated rockets, normal/Infinity arrow and rocket consumption,
actual inventory/offhand stock references, exact potion/custom-component variants,
deterministic wrap, no selection mutation, packet dedup/throttle, moved stock,
exhaustion and empty feedback, forged/stale requests and changed owner/class/run.
Crossbows use native charge ticks and actual firing, including Multishot's additional
native intangible markers, durability, current-load preservation and late run denial.
Spawner tests exercise real server use-on plus item fallback, authoring/vetoes,
saved components, native ranged-goal reassessment/owned moving arrow, and warning resets.
Unit regressions cover input modifier keys and payload shape/empty-wire bounds.

TESTING (licensed client/world/co-op acceptance):
1. In Controls, use default R, then rebind/unbind and modifier/mouse/conflicting chords.
   Hold/release through chat, inventory, another modal and focus changes: no queued cycle.
   Check two GUI scales, long authored names, icon, actual current key and next-load label.
2. Load/fire Cinderkiss, Cinderbite and Cindermaul from inventory and each usable hand
   in bows/crossbows. Confirm authored visuals/damage, stock, enchantments and Infinity/
   Multishot behavior in the real run. Cycle normal/spectral/tipped/custom variants;
   exhaust one/all types and see one appropriate automatic switch/out-of-ammo notice.
3. Change class/run/ownership after selecting or charging; unauthorized ammunition must
   not fire. Relog, respawn and travel: no stale client selection authorizes use.
4. Aim/draw/load/fire near a Cosmic Spawner without title spam or preset changes.
   Developer Shift-copy an authored bow and a loaded crossbow: copy without firing.
   Spawn/reload the skeleton and observe native ranged combat. Wrong-tool mining warns
   only after a fresh uninterrupted second and respects tool/slot/target changes.
5. Existing licensed recommendations remain in
   [the active ledger](BATCH_1_7_20_REVIEW_NOTES_20261012.md), including unreproduced player
