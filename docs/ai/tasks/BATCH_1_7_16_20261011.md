# Batch16: Drops and presets - 1.7.16-alpha.1
Approved scope: [series plan](ALPHA_1_7_BATCH_PLAN_20261010.md), card16 and its spawner editor specification. Stop after16.

## Implemented
- Developer /spawner edit > Drops / files opens gear percentages, native/default loot inspection, configured rules and named preset management. Nested Save loot changes only the parent draft; main Apply commits the complete validated draft.
- Six independent equipment drop percentages accept0-100; untouched native/legacy values retain their original ownership. Defaults show conservative base probabilities only when the table can be interpreted safely. Conditional/contextual/group/function/provider cases explicitly have no fixed percentage; normal loot conditions and looting are not presented as guarantees.
- Selecting a native row drafts an explicit override, which replaces matching native item drops and bypasses their conditions. Custom additions independently roll after native drops; duplicate item rows use separate stable IDs. Counts are1-64, chances finite0-100; deleting every configured rule explicitly restores native loot. Existing equipment-drop protection remains.
- Searchable paginated preset browse, Save, confirmed Overwrite, Load, confirmed Delete, and assigning/clearing all five existing shortcuts. Save exports the complete current draft without applying it. Load gets a fresh session and dirty draft; main Apply is required, and Cancel discards the load.
- Fresh Developer/ray target/range/session/concurrency checks precede all world or file mutations. Bounded operation IDs suppress duplicate file actions, requests are rate limited, and pending client operations lock controls. Library is bounded to256 named files; names reject traversal/reserved devices, linked paths are refused, files are capped at256KiB, and replacement is atomic or fails without replacing the old file.
- Format4 JSON stores typed full configuration as SNBT, including native spawn knobs, weighted entries, equipment components, flags and loot. Identity, current spawn delay and one-shot progress are excluded; applying a preset resets progress and delay intentionally. Existing shortcuts use this same compatible loader.
- Formats1-3 remain partial overlays, preserving native settings absent from the old file. Current/unknown block, preset and wrapper fields survive; untouched legacy/future-kind loot rows retain raw data. Newer unsupported schemas fail closed. Unknown file wrapper metadata travels with the block and is re-exported, including to another filename.

## Compatibility and resource cost
Network protocol32 ->33 requires matching client/server versions. Block schema153 ->154 records optional opaque preset-file metadata; preset schema remains5, export format3 ->4. Existing blocks lazily upgrade when loaded/saved with the usual log, without scanning unloaded chunks. Legacy files are read without rewriting; explicit next Save uses format4. Back up worlds/preset files before upgrade; rollback uses the matching prior build and backup, not an older writer on newer data.
One bounded draft/held snapshot per open Developer session, at most128 rule rows,256 inspection rows,256 operation IDs and one last reply; no every-tick file/world/inventory scans. Library/table reads are on demand. No new dependency or server resource-setting changes. Authored class chests/loadouts/rockets remain untouched.
