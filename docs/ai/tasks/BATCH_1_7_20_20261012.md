## Compatibility and resource cost

No registry IDs, authored chest contents/loadouts, unknown spawner payloads, runtime dependencies, heap or worker budgets are changed. Current schema additions are confined to an optional versioned Chop proof within the existing trade plan. Old ordinary plans decode with an empty proof. Old committed Chop plans without sufficient registry proof remain held for complete-save review instead of silently granting ownership. Settle pending trades before downgrade; retain complete world/player/account saves together.

Raw Chops trade subject to existing one-personal-Chop and active-run binding. Bound return Chops require the recipient's own outside-active inventory escrow in the same active run. A trade does not transfer another player's saved inventory or grant dungeon membership. Invalid capacity/entitlement cancels before account reservation and returns the original offers. New Chop trades add one paired registry save and one account acknowledgement before item delivery; ordinary trade plans do not add those writes.

Craft source selection reuses the already detached allocation inventories. No polling cadence, extra packet stream or runtime dependency is added. Metrics remain event-driven with one active run checkpoint per100ticks,64 recent resource records plus immutable bounded segments; durable historical files grow with actual runs/events.
